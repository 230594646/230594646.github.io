## 🤝 Agile Team Charter ##
### Evidence ###
<img width="1920" height="1080" alt="Agile Team Charter" src="https://github.com/user-attachments/assets/899da6ef-a717-4b46-bc23-f77765d9d3e1" />

### Reflection ###
The Agile Team Charter helped the team establish clear expectations for communication, collaboration and development. It kept us focused on the goal of creating a multiplayer chess game and encouraged us to discuss features, break down tasks and review each other's work.

However, the charter had some shortcomings. It did not clearly define individual responsibilities, how disagreements should be handled, or how progress should be documented. The Definition of Done was also quite basic and could have included documentation and integration requirements.

Overall, the charter provided a useful foundation, but it could have been more detailed and adapted as the project became more complex.

## 👤 User Stories and Tasks ##
### Evidence ###
<img width="1592" height="1107" alt="User Stories and Tasks" src="https://github.com/user-attachments/assets/5dcce295-38d2-4148-ab18-aafac550fdb0" />

### Reflection ###
The user stories and tasks helped the team break the Chaotic Chess project into smaller and more manageable features. Assigning priorities also helped us identify which features were more important to the core gameplay. 

However, some features, such as random events and bonus actions, became more complex than expected, requiring additional work during development. Some tasks also changed as we discovered new requirements or problems.

Overall, the user stories provided a useful development structure while allowing flexibility when new requirements and challenges arose.
